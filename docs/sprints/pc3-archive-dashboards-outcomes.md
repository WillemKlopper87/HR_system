### PC-3 — Archive, dashboards, outcomes

**Status: done** (2026-08-19, commit `794681e`) — see `hcm/backend/performance/` (`services/agreements.py::archive_period`, `views_agreements.py::PerformancePeriodViewSet.archive/.rating_distribution`, `models/agreements.py::ImprovementPlan` + migration `0004`, `views_agreements.py::ImprovementPlanViewSet`, `test_pc3.py`), `hcm/backend/core_hr/management/commands/seed_demo_data.py` (new `auditor` demo login), and `hcm/frontend/src/pages/{PerformancePeriodsPage,PerformanceRecordsPage,MyPerformancePage,TeamPerformancePage}.tsx` + `e2e/performance.spec.ts` (extended with a third describe block, not a new file).

**Implementation notes:**
- *Archive is permissive, not all-or-nothing.* `archive_period` moves every `FINAL_SIGNED` agreement to `ARCHIVED` and the period itself to `ARCHIVED` regardless of stragglers — a real FY doesn't stay open forever for one holdout — and reports `{archived, outstanding}` so hr_admin sees exactly what happened, the same "report, don't block" shape `generate_agreements_for_period` already uses. `PerformancePeriod.Status.ARCHIVED`/`PerformanceAgreement.Status.ARCHIVED` and the code that treats them as terminal (`active_stage_for`, `stage_is_signed`, `current_stage`) already existed from PC-1 — only the transition itself was missing.
- *Rating distribution reuses the small-cell-suppression convention exactly* (`ee_reporting._suppress_matrix` / `core_hr.headcount_dashboard`'s `SMALL_CELL_THRESHOLD = 5`, same `can_see_unsuppressed_aggregates(employee, FieldTier.SENSITIVE)` gate) — crossing a rating with a small division can point back at one individual's score, the same privacy shape as EE's demographic breakdowns, so it gets the same treatment rather than inventing a new rule.
- *The evidence "manifest" is a computed view, not a new model* — `PerformanceAgreementSerializer` already nested `documents`/`signatures`/`elements[].evidence_items` from PC-1/PC-2; PC-3's only gap was that **nobody could reach it** — `auditor` had zero performance-related UI anywhere in the app (confirmed: no nav entry, no seeded login even existed). Fixed with a new `/performance-records` page (hr_admin + auditor, org-wide, unscoped) that flattens the already-nested data into a documents / signature-trail / evidence-manifest view, and a new seeded `auditor`/`auditor123` demo login (`seed_demo_data.py`) — the first one this codebase has ever had, retroactively also making the EE equity dashboard's auditor path browser-testable for the first time.
- *`ImprovementPlan`* is deliberately a stub, not a workflow: one `review_date` (not a schedule), an `outcome` enum (`open/resolved/escalated/cancelled`) updated by hand, gated server-side (`ImprovementPlanSerializer.validate`) and client-side on `agreement.hr_attention`. Write access is narrower than the agreement's own `can_act_on_agreement` — only the Head or hr_admin can open or update one (`ImprovementPlanViewSet._assert_can_drive`), never the employee it's about; the employee sees the same record read-only on their own `/my-performance`.
- *Head team view* gained `final_score`/`hr_attention` columns directly on `/team-performance`'s table (previously only visible after opening one agreement at a time) — the smallest read of "Head team view" from the backlog that was still missing after PC-1/PC-2.
- *Legacy Reviews retirement* removed the `Reviews`/`Review Cycles` nav links (`navConfig.ts`) but deliberately left the backend viewsets, `ReviewsPage`/`ReviewCyclesPage`/`ReviewDetailPage`, and `sync_legacy_review` (PC-2) untouched — a period with `legacy_cycle` set still has real historical data behind those routes, so "retire" means "stop promoting", not delete.
- *Deferred, not silently dropped:* the two "Optional" integrations (final band → `compensation.CompProposal` draft, PDP → `learning.TrainingRecord(REQUESTED)`) were left undone — the backlog itself marks them optional, and this sprint was already the largest since PC-1. Left `[ ]` below rather than checked.

**A defect found by verification, fixed:** the new `getByLabel('Outcome', {exact:true})` e2e locator hung for the full 45s timeout even though the element visibly existed in the failure screenshot — `<label>Outcome<select><option>Open</option>…</select></label>`'s raw `textContent` is `"OutcomeOpenResolvedEscalatedCancelled"` (options included), which is what Playwright's *exact* label-text matching compares against, not the browser's actual computed accessible name (`"Outcome"`, shown correctly in the ARIA snapshot) that the *non-exact* substring match had been silently relying on. Switched to `getByRole('combobox', { name: 'Outcome', exact: true })`, which uses real accname computation. A real trap for any `<label>Text<select>…options…</select></label>` pattern elsewhere in this codebase, not unique to this component.
