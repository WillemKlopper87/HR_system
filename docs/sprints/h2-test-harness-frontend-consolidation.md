### H2 — Test harness + frontend consolidation

**Status: done** (2026-08-18) — see `hcm/frontend/e2e/` + `playwright.config.ts` (23 real-browser tests, `npm test`, CI `e2e` job), `frontend/src/api/hooks.ts` (`useApiQuery`/`useAllPages`/`useMutation`), `layout/navConfig.ts`, `components/Field.tsx`, `lib/format.ts`, `rbac_audit/test_access_matrix.py`, `rbac_audit/test_module_boundaries.py`, `policies/extraction.py` (content sniffing).

**Implementation notes:**
- *Playwright suite* — `playwright.config.ts` starts two servers itself: Django on a throwaway, freshly migrated + `seed_demo_data`'d SQLite DB (`e2e/backend-server.mjs`, via the new `SQLITE_PATH` settings override) and the Vite dev server proxying `/api`. 23 tests across six spec files reproduce, as code, the by-hand verification paragraphs of every prior sprint: auth + guards (incl. H1's session-expiry bounce), core HR (list/search/detail, org-structure CRUD, data-quality, headcount, per-role row scope), recruitment (create requisition, applicant detail, dashboard, module fences), performance/learning/assessments, compensation with a **genuine TOTP enrol → confirm → challenge flow** (`e2e/helpers.ts::totp` is an RFC 6238 implementation, so the test computes codes exactly as an authenticator app would), grant reuse and no cross-user leakage, EE reporting, workforce integrity, ESS (edit own phone), policies (acknowledge; hr_admin library + compliance). Runs in ~1.8 min. `workers: 1` on purpose — one seeded backend, a few mutating specs.
- *What the suite found on day one:* (1) after an explicit Sign out the next login returned to the previous user's last page — H1's return-to state leaked into logout; `RequireAuth` now passes `from` only for expiry/deep-link. (2) an intermittent 500 on TOTP enrolment under load: SQLite's classic "database is locked" (a DEFERRED transaction that has already read cannot wait for the write lock) with the threaded dev server + a browser's parallel requests — fixed at the source with `transaction_mode: IMMEDIATE` + a 20 s busy timeout on the SQLite fallback (Postgres unaffected). Both were invisible to 425 backend tests.
- *Shared fetch layer* — `useApiQuery(fetcher, deps)` owns loading/data/error, a stale-response guard (only the newest in-flight request may set state — `EmployeeListPage` had hand-rolled a `cancelled` flag for this, nobody else had), the `ApiError`→message mapping and `reload()`; `useAllPages(path)` sugar; `useMutation` for busy/error around actions. Migrated 19 pages (list pages, dashboards, ESS, `EmployeeListPage`, `ReviewsPage`, `WorkforceIntegrityPage`…): **445 lines deleted / 207 added in pages+layout, plus ~150 new in the shared modules — net ≈ −240 in pages, ≈ −90 overall.** The roadmap's "≥ 1 000 lines" guess was wrong: the bulk of the duplication is the 22 `New*Form` components, which were *not* migrated to `useMutation` in this pass (each is a hand-written form with bespoke validation — mechanical rewriting risks behaviour drift for little gain; the hook exists for new forms and for whoever touches those files next). Detail-page monoliths (`EmployeeDetailPage`, `ApplicantDetailPage`, `EEConfigurationPage`) untouched.
- *Dedupes* — the byte-identical `Field` (RBAC "Restricted" badge renderer) now lives in `components/Field.tsx`; `formatZAR` in `lib/format.ts`; the 27 hand-written `NavLink`s in `AppShell.tsx` became a `NAV_ITEMS` config array with the role gate next to each label (`layout/navConfig.ts`) — adding a page is one entry + one route.
- *Golden access matrix* (`rbac_audit/test_access_matrix.py`) — for all 33 router endpoints × 7 seeded roles, asserts the exact (list GET, bare POST) status pair, generated against the real seeded system, reviewed against `RBAC-Roles.md`, and frozen so any widening/narrowing has to be reviewed on purpose; a second test asserts no endpoint ever answers a bare POST with a 500; a third asserts the three Restricted payroll endpoints are 403 for every non-payroll role. **The sweep found two real defects:** `EEReportViewSet` kept `post` for its named actions without disabling `create()`, so an empty POST reached an all-read-only serializer and 500'd with an IntegrityError (now an explicit 405); and `RemunerationRecordViewSet` used the module's coarse `EEReportingPermission`, so **ee_manager and accounting_officer could list raw per-employee remuneration** (behind step-up, which they can self-enrol) although `RBAC-Roles.md` gives neither pay access — now `RemunerationRecordPermission` (hr_admin RW, auditor R; EEA4 generation reads the table at the ORM layer so the review/sign-off chain is unaffected), and `EEConfigurationPage` no longer renders the Remuneration section for other roles.
- *Module boundaries as a test* (`rbac_audit/test_module_boundaries.py`) — `ast`-walks every app's production modules and fails on any peer-app import that isn't a `<app>.queries` seam (tests, migrations and `seed_demo_data.py` exempt, as the README documents); also asserts the shared kernel imports no domain app and that every `queries.py` is read-only. Passed first time — the rule really was being honoured; now it can't silently stop being.
- *Upload sniffing* (`policies/extraction.py`, brief D4) — the extension picks the parser but is no longer trusted: `%PDF-` / `PK\x03\x04` (+ `word/document.xml`) / no-NUL-bytes are checked first and parser exceptions are wrapped, so a mislabelled or corrupt file is a clean 400 with a specific message instead of a 500 from pypdf/python-docx.
- *Not done:* the ZAP Low/Informational triage (141 + 1 021 alerts from the 2026-08-13 scan) — needs a fresh authenticated ZAP run and a person deciding what "informational" means for this system; moved to H3/UAT-1's security pass rather than pretending a grep is a triage.

**Architecture / design tension:** the golden matrix trades flexibility for safety — every deliberate permission change now costs a one-line edit to `EXPECTED` plus a sentence of justification in the commit, which is exactly the friction wanted for RBAC. The fetch hook deliberately keeps each page's own action `error` state separate from `loadError` rather than merging them into one; merging would have hidden which of the two failed.

**Verification:** `manage.py check --fail-level WARNING`, `makemigrations --check --dry-run`, `manage.py test` — **435/435** (425 prior + 3 access-matrix, 3 module-boundary, 4 upload-sniff). Frontend `oxlint` (2 pre-existing fast-refresh warnings), `tsc -b && vite build`, and **`npm test` 23/23** twice in a row after the SQLite fix (previously 1 intermittent failure in 4 runs). Real-browser: the suite *is* the browser verification now — every role login, every module page, plus the two mutations-with-refresh (contact details, org-structure department create/delete) and the full TOTP flow.
