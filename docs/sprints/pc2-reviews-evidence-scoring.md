### PC-2 — Reviews, evidence, scoring

**Status: done** (2026-08-19, commit `96c0c9c`) — see `hcm/backend/performance/` (`models/agreements.py::EvidenceItem` + migration `0003`, `services/agreements.py` (`STAGE_FLOW`/`STAGE_ELEMENT_FIELDS`/`STAGE_HEAD_FIELDS`/`active_stage_for`/`_finalize_scoring`/`sync_legacy_review`/`validate_final_ratings_complete`/`validate_evidence_for_final`), `permissions.py::can_act_on_agreement`, `serializers_agreements.py` (`EvidenceItemSerializer`, extended `AgreementElementSerializer`), `views_agreements.py::EvidenceItemViewSet`, `evidence.py` (file sniff + 20 MB cap), `test_reviews.py`), and `hcm/frontend/src/pages/MyPerformancePage.tsx` (`ReviewSection`/`TextCell`/`RatingCell`/`EvidencePanel`) + `e2e/performance.spec.ts` (extended, not a new file — see below).

**Implementation notes:**
- *One state machine, three stages.* PC-1's contracting-only sign/open logic is generalized into `STAGE_FLOW` (one row per stage: `open_status`/`employee_signed_status`/`head_signed_status`/`employee_error`), so mid-year and final reuse the exact employee-then-Head signing order, password-re-auth-or-TOTP, PDF-snapshot-and-hash, and delegation rules PC-1 already proved — no new signing code, only a new stage row: `agreed ──open(midyear)──▶ midyear_open ──sign×2──▶ midyear_signed ──open(final)──▶ final_open ──sign×2──▶ final_signed`. `open_phase` is genuinely period-wide (every AGREED agreement moves together; FINAL accepts either AGREED or MIDYEAR_SIGNED, so an org that skips mid-year one year still reaches final cleanly).
- *Field editability is per-field, not per-stage.* `AgreementElementSerializer.validate()` gates `q2_*`/`final_*` writes against `STAGE_FLOW`: the employee's own fields (target note, rating, own comment) are writable only at that stage's `*_open` status; the Head's comment (`STAGE_HEAD_FIELDS`) stays writable one status longer — through `*_employee_signed` — so the Head can react to what the employee just signed before signing themself, mirroring how contracting already lets the Head act after the employee submits.
- *Evidence* (`EvidenceItem`): file (sniffed against a magic-byte allowlist — PDF/JPEG/PNG/GIF/Office-zip/plain-text, 20 MB cap, `evidence.py`) or an https-only link (OneDrive/Teams/SharePoint stays off-platform on purpose); sha256 computed server-side; downloads go through the same authenticated-route pattern as `policies`, never a raw `MEDIA_URL`. Tagged with the *display* stage (`agreement.current_stage`), not the *signable* stage (`active_stage_for`), on purpose — evidence must stay addable after a stage is fully signed (`added_after_signoff` exists precisely for that), which the stricter "currently actionable" view would have blocked. Never hard-deleted once its stage is signed (`stage_is_signed`).
- *Scoring.* `_finalize_scoring` runs on the Head's final signature: `final_score = Σ(weight × rating)`, `hr_attention` set when the final score or any single KPI rating is below `period.attention_threshold` (or the phase is overdue), with the reason recorded alongside for the Head's own team view.
- *Legacy bridge.* `sync_legacy_review` derives a Sprint 6-7 `Review` row from the finished agreement when `period.legacy_cycle` is set (nullable — PC-1 already wired this link), so the old review pages keep showing something without a schema migration of their own; no `legacy_cycle` means no `Review` row and nothing breaks.
- *Frontend:* `ReviewSection` on `/my-performance` renders the Q2 or Q4 table for whichever stage is current (`null` during contracting), each cell independently editable per the same per-field window the API enforces; the header shows `final_score`/`hr_attention` once final is signed; `/performance-periods` now has one "Open {phase}" button per phase row (was a single hardcoded "Open contracting" action).
- *e2e test-suite mechanics, not product code:* `MyPerformancePage`/`TeamPerformancePage` were missing the `<p className="empty-state">Loading…</p>` state every other list page renders (`PayBandsPage`, `RequisitionsPage`, …) — added, closing a real (if minor) UI flash-of-empty-content gap the new tests happened to expose. The new Q2/Q4 browser flow is appended to `performance.spec.ts` (not a separate file): it drives the same fixed `employee`/`manager` demo login PC-1's tests use through a full year, and `playwright.config.ts` only guarantees execution order *within* one file (`workers: 1`, `fullyParallel: false`) — a separate file sorted unpredictably relative to `performance.spec.ts` under the project's directory-glob discovery, occasionally running before it and leaving the PC-1 test's agreement already signed. `e2e/backend-server.mjs` also now raises the e2e-only login-throttle env vars (`THROTTLE_LOGIN_USERNAME`/`THROTTLE_LOGIN_BURST`) — the merged file's ~20 logins against 3 fixed demo accounts in one run started tripping H1's real (and correctly working) 10/min per-username throttle.

**Two defects found by verification, both fixed rather than worked around:**
1. *Evidence upload had no authority check.* `EvidenceItemViewSet.perform_create` relied on DRF's `has_permission` (checked for POST/create) plus `has_object_permission` (checked only once an object exists) — since there's no existing object at create time, neither ever verified the actor could act on the *agreement* the evidence was being attached to. Any authenticated employee could have attached evidence to anyone's agreement. Caught by `test_auditor_can_read_but_not_upload_evidence` returning 201 instead of 403; fixed with an explicit `can_act_on_agreement()` check inside `perform_create`.
2. *The Head's own comment field was unreachable.* The first cut of the stage-field gate allowed edits only "exactly at that stage's `*_open` status" — which also locked the Head out of `q2_head_comment`/`final_head_comment` the instant the employee signed, since that transition leaves `*_open`. No unit test caught this (each field was tested in isolation against its own stage's open window); the new browser flow did, failing at the Head's "add a comment, then sign" step. Fixed with `STAGE_HEAD_FIELDS`' one-status-longer window (see above), plus two new backend tests (`test_head_comment_stays_editable_after_the_employee_signs`, `test_final_head_comment_stays_editable_after_the_employee_signs`) covering exactly this.
