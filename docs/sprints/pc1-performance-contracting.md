### PC-1 — Performance periods, templates, contracting, reminders, delegation (ADR-010)

**Status: done** (2026-08-18, commit `6bcb396`) — see `hcm/backend/performance/` (models/ and services/ are now packages: `cycles.py` = the legacy Sprint 6-7 review, `agreements.py` = this), `pdf.py`, `reminders.py`, `tasks.py`, `permissions.py`, `serializers_agreements.py`, `views_agreements.py`, migration `0002`, and `hcm/frontend/src/pages/{MyPerformance,TeamPerformance,PerformancePeriods}Page.tsx` + `e2e/performance.spec.ts`.

**Implementation notes:**
- *Shaped by the real workbook, not a generic PMDS.* `PerformancePeriod` is one FY (1 Apr–31 Mar, user-confirmed) with three `PeriodPhase` windows; `AgreementTemplate` → `TemplateSection` (the year's Objectives/Perspectives — the corporate strategy, which genuinely changed between the two real scorecards, hence versioned templates) → `TemplateElement` (KPA, KPI, metric, default weight, **`level_descriptors` {1..5}** — the workbook writes a different target per rating level, which a naive "one target per KPI" model would have lost). Templates target job grades / occupational levels / departments; `pick_template` prefers the period-pinned one, newest version first.
- *The rules that are actually enforced:* weights must total **1.00** and every KPI needs all five descriptors before an agreement can be submitted (and before a template can be published); only the employee submits their own; a return needs a reason; the **employee signs first, then the Head** — the Head's attempt before that is a 409 with a plain-English reason, not a silent no-op; a second identical signature is refused; `hr_admin` can administer everything and sign **nothing**.
- *Signing (ECT Act ordinary electronic signature).* Signing generates the stage/revision PDF **first**, hashes it, and stores that sha256 on an immutable `AgreementSignature` along with actor, time, method, IP/UA — so "what did I sign" stays answerable. Identity is proven by password re-authentication, or by the ADR-009 TOTP step-up grant when the template says so (`signature_method` per template, so an executive population can be held to a higher bar without changing code). `pdf.py` deliberately renders the workbook's own grid (objective spanning its KPI rows, sub-totals, PDP, signature block) and is kept deterministic — its bytes are what the hash commits to.
- *Delegation* (`SigningDelegation`): the user's rule — the Head signs before going on leave, otherwise "a person designated by the boss has authority". Dated, revocable, created by the Head or hr_admin, audit-logged; the delegate's signature reads *signed by X acting for Y*, never as Y. Outside the window it is refused exactly like any other third party.
- *Amendments* are the workbook's Rev3/Rev4 counters made real: revision + 1, back to draft, earlier revisions' signatures and PDFs kept as history (they are what was agreed then), a reason required.
- *Reminders (ADR-011's HCM half)* — the reason this sprint exists at all, in the user's words: KPIs get forgotten until it is a last-minute rush. `reminders.py` runs daily (Celery beat), works out which configured offset falls today (`[28, 14, 7, 1]` days before, then every 7 days overdue — **editable per phase by hr_admin in the UI**), and for the *open* phase pushes: one collab work item per outstanding employee (`hcm:agreement:{id}:{stage}`, priority rising low→normal→high→urgent, deep-linked back to the HCM), a "N of your team outstanding" digest per Head, and a **critical** department announcement at phase open and first overdue. Every emission is keyed in `ReminderLog`, so the job is safe to re-run; a collab outage is recorded and retried next run, never fatal; with `COLLAB_ENABLED=0` the run still reports who is outstanding and says plainly that it delivered nothing.
- *Frontend:* `/my-performance` (the scorecard grid, inline weight editing with the live 100% check, submit, and a signature panel that says **why** a button is disabled), `/team-performance` (the Head's queue, return/approve/sign, and the delegation form), `/performance-periods` (hr_admin: phase windows, the editable reminder ladder, contracting completion by division, template list). All three use H2's shared fetch hooks.
- *Seed:* a live 2026/27 round — a published Sentech-shaped template (3 objectives, 6 weighted KPIs, real target wording), 151 agreements, **most still in draft** (the honest starting point the reminder engine exists for), a few submitted/approved, and 3 genuinely signed with real hashed PDFs (the seed signs through the service, so nothing is faked).

**Architecture / design tension:** `PerformancePeriod` is a *new* model with a nullable link to the legacy `ReviewCycle` rather than a rename — PC-2 will derive the old single rating from the agreement's final score while the Sprint 6-7 pages still work, and only then retire them. The bigger tension is the reminder engine's dependency direction: it would have been easy to let `integrations.collab` know about agreements, which would have made the code shorter and the coupling permanent. It stays domain-agnostic (titles, refs and deep links are composed here), which is what let `integrations` be reclassified as shared infrastructure when the module-boundary test flagged the import — see below.

**Two defects found by verification, both fixed rather than worked around:**
1. *Query storm on detail routes.* `get_queryset` filtered **every** agreement through a per-row reporting-chain walk, so a single `can-sign` request ran hundreds of queries and the signature panel simply never appeared in the browser. Caught by the new e2e spec (requests hanging in the trace, not a test bug). Detail routes now resolve the object and let the object permission decide; lists use the shared `row_scoped_queryset` plus one delegation predicate. A detail request for someone else's scorecard still answers **404, not 403** (`_HideForbiddenAsNotFound`) so it doesn't confirm the record exists.
2. *Module boundary.* H2's `test_module_boundaries` flagged `performance → integrations`. Resolved by classifying `integrations` as shared infrastructure alongside `core_hr`/`rbac_audit` (it is an outbound adapter that knows nothing about the domain), not by exempting the file — and the kernel half of that test now keeps it honest.
